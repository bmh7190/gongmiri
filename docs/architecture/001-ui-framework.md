# ADR 001: React로 UI 프레임워크 전환

- 상태: 승인
- 작성일: 2026-08-30
- 결정: Vue 3 UI를 React로 전환하고 이후 UI 개발을 React 기준으로 진행한다.

## 배경

공미리는 다국어 지원과 전체 화면 UI 개편을 앞두고 있다. 현재 `App.vue`와 `MapPanel.vue`에 상태, 파일 처리, Worker 통신, MapLibre 수명주기와 화면 표현이 집중돼 있다. 단순히 Vue 컴포넌트를 나누는 대신, 장기 유지보수 기술을 React로 통일하면서 책임 경계도 함께 다시 설계하기로 했다.

현재 `src/`에는 Vue SFC 13개, 약 4,881줄과 TypeScript 9개, 약 751줄이 있다. `App.vue`, `MapPanel.vue`, `DataGrid.vue`, `VisualizationPanel.vue` 네 파일이 Vue 코드의 약 75%를 차지한다. 따라서 이번 작업은 문법 치환이 아니라 UI 계층의 재작성으로 취급한다.

## 목표

- 앞으로의 UI 개발과 유지보수를 React 기준으로 통일한다.
- 파서, SRID, 통계, 시각화 계산을 프레임워크 독립적인 TypeScript로 보존한다.
- 기존 책임 집중을 거대한 `App.tsx`나 `MapPanel.tsx`로 그대로 옮기지 않는다.
- 다국어와 UI 개편을 한 번만 구현한다.
- 마이그레이션 과정에서도 비교 가능한 기준 빌드와 샘플 데이터 동작을 유지한다.

## 고려한 대안

### Vue 3 유지 후 리팩터링

재작성 비용과 회귀 위험은 가장 낮지만, UI 개편과 다국어 작업을 Vue에 먼저 투자한 뒤 장기적으로 React로 옮기면 화면 작업이 중복된다. React를 장기 기술 방향으로 선택했으므로 제외한다.

### Vue와 React를 장기간 혼용

점진적으로 보이지만 상태·스타일·다국어 런타임이 이중화되고 최종 제거 시점이 흐려진다. 마이그레이션 기간의 기존 Vue는 비교 기준으로만 유지하며, 배포 결과에 두 런타임을 함께 포함하지 않는다.

### React와 확장 프레임워크를 동시에 교체

React 전환과 함께 WXT나 Plasmo까지 도입하면 UI 회귀와 빌드·권한 문제의 원인을 분리하기 어렵다. 이번에는 Vite와 CRXJS를 유지한다. 브라우저별 배포 또는 다중 entrypoint 요구가 생기면 별도 ADR로 검토한다.

## 목표 구조

```text
src/
  app/                    # 앱 조립과 최상위 레이아웃
  domain/                 # 프레임워크 독립 타입과 계산
  features/
    file-upload/
    dataset-parser/
    projection/
    map-viewer/
    attribute-table/
    visualization/
  shared/
    components/
    hooks/
    i18n/
    styles/
  workers/
```

## 마이그레이션 방식

1. 현재 프로덕션 빌드와 대표 샘플 ZIP의 동작을 기준선으로 기록한다.
2. Vue 파일 안의 순수 로직을 `domain/`과 feature 모듈로 이동한다.
3. React, React DOM, React용 Vite 플러그인과 다국어 런타임을 구성한다.
4. 파일 업로드 → ZIP 검사 → Worker 파싱 → 결과 요약의 첫 수직 기능을 이식한다.
5. MapLibre 지도와 선택 상태를 이식한다.
6. 속성 테이블, 가상 스크롤, 시각화 설정을 이식한다.
7. 기능 동등성을 확인한 뒤 Vue entrypoint와 의존성을 제거한다.
8. React 구조 위에서 다국어 전체 전환과 UI 개편을 진행한다.

각 단계에서는 같은 소스 트리에 이전 Vue 코드를 비교 기준으로 둘 수 있지만, 프로덕션 진입점은 한 프레임워크만 사용한다.

각 기능은 기존 화면을 그대로 복제하지 않는다. 도메인 결과와 사용자 작업 흐름을 보존하면서 컴포넌트 책임, 로딩·오류 상태, 반응형 배치, 접근성과 다국어를 해당 이식 단계에서 함께 개선한다. 반면 검색·내보내기·다운로드 감지처럼 기능 범위를 넓히는 작업은 마이그레이션 완료 후 별도 단계로 유지한다.

## 기능 동등성 기준

- 동일 ZIP에서 피처 수, 속성 값, 컬럼 통계와 지오메트리 유형이 일치한다.
- 지원 SRID 재투영 결과가 허용 오차 안에서 일치한다.
- 지도와 테이블 선택이 양방향으로 동기화된다.
- Quick/Full 모드와 대용량 경고가 동일하게 동작한다.
- 인코딩 변경 후 재파싱이 가능하다.
- Chrome 확장 아이콘에서 전체 화면 뷰어가 정상적으로 열린다.

## 위험과 대응

- 지도 수명주기 회귀: MapLibre 어댑터를 별도 hook으로 격리하고 생성·해제를 검증한다.
- Worker 경쟁 상태: 작업 ID와 취소 정책을 UI와 분리된 모듈로 유지한다.
- UI 기능 누락: 기존 화면별 기능 체크리스트로 동등성을 확인한다.
- 번들 증가: Vue와 React를 함께 배포하지 않고 지도 모듈 지연 로딩을 적용한다.
- 일정 장기화: 새 기능을 잠시 동결하고 업로드부터 테이블까지 수직 단위로 완료한다.

## 결과

이번 결정으로 기존 Vue용 `vue-i18n` 기반은 확장하지 않는다. React 다국어 기반이 준비되면 Vue 관련 코드와 의존성을 제거한다. 파서와 좌표계 등 순수 TypeScript 로직은 최대한 변경 없이 재사용한다.

## 적용 결과

2026-08-31 프로덕션 진입점과 기능 이식을 React로 완료했다. 로컬 브라우저 비교와 자동 회귀 검사를 기준으로 Vue SFC, Vue 전용 진입점·타입 설정, `vue`, `vue-i18n`, `vue-tsc` 및 Vite Vue 플러그인을 제거했다. 실제 Chrome의 권한과 서비스 워커 동작 검증은 별도 릴리스 체크리스트에서 추적한다.
